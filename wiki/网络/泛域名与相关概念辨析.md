## 1.1 一张图先把层级摆清楚

域名是**从右往左**、按 `.` 分级的。以 `s1-zhangjiahui04.test.zhuanspirit.com` 为例:

```
s1-zhangjiahui04 . test . zhuanspirit . com .
└── 4级(主机)  └3级 └── 2级(注册域)  └顶级 └根(隐藏)
```

- **根域**:最右边那个看不见的 `.`,全球 13 组根服务器。
- **顶级域 TLD**:`com`、`cn`、`org` 这些。
- **注册域 / 二级域**:`zhuanspirit.com`——你花钱买下来、能自己管理的那一层。
- **子域**:在注册域左边继续加的层级,`test.zhuanspirit.com`、`oa.zhuanspirit.com` 都是子域。
- **主机名**:最左边那段,通常对应一台机器/一个服务。

关键认知:**你买的是 `zhuanspirit.com` 这一个域名,它左边的所有层级都归你自由支配**,想加多少子域、加几级,都是你在自己的 DNS 里说了算,不用再花钱、不用再向注册商申请。

---

## 1.2 子域名(subdomain)

子域名就是在你拥有的域名左边加前缀,得到的一个**具体的、写死的**名字:

```
oa.zhuanspirit.com
api.zhuanspirit.com
blog.zhuanspirit.com
```

每一个都是一条独立的、明确的 DNS 记录。你要新增一个 `shop.zhuanspirit.com`,就得去 DNS 里**手动再加一条**记录。有一百个子域,原则上就要配一百条(或用泛解析,见下)。

> 常见误区:很多人以为「子域名要单独买」。不需要。子域名是你已购域名的免费衍生,数量不限,只受你 DNS 服务能配多少条记录的限制。

---

## 1.3 泛域名 / 通配符域名(wildcard domain)

泛域名是用一个 `*` 通配符,一次性匹配**某一层的任意名字**:

```
*.zhuanspirit.com
```

它能匹配 `a.zhuanspirit.com`、`b.zhuanspirit.com`、`oa.zhuanspirit.com`……**任何**在这一层的前缀,而不用一条条列出来。

对应到引出这个系列的内部场景:开发者不再需要为每个人、每台机器单独配一条子域,而是用一条 `*.test.zhuanspirit.com` 泛域名,让 `oa-zhangjiahui04.test.zhuanspirit.com`、`oa-lisi.test.zhuanspirit.com` 全都自动生效。谁申请机器,谁的名字就能直接用,免去手动加记录、免去来回切代理。

**`*` 的匹配规则(重要,后面证书那篇还会用到):**

- `*` 只匹配**一个层级**。`*.zhuanspirit.com` 能匹配 `oa.zhuanspirit.com`,**但不能**匹配 `a.b.zhuanspirit.com`(那是两级)。
- `*` 只能出现在**最左边**,不能写成 `oa.*.com` 或 `a.*.zhuanspirit.com`。
- 要覆盖更深的层级(如 `*.test.zhuanspirit.com`),就得针对那一层单独配泛记录/泛证书。

这条「只匹配一层」的规则是泛域名、泛解析、通配符证书三者共同的硬约束,记住它能省很多坑。

---

## 1.4 泛解析(wildcard DNS record)

这里最容易和「泛域名」混。区分方式:

- **泛域名**是一个**概念 / 名字形态**(带 `*` 的域名)。
- **泛解析**是让这个泛域名生效的**具体手段**——在 DNS 里加一条 `*` 记录。

```
# DNS 区域文件里的一条泛解析记录
*.test.zhuanspirit.com.   A   192.168.170.88
```

配了这条之后,任何 `xxx.test.zhuanspirit.com` 只要 DNS 里**没有更精确的记录**,就都会落到 `192.168.170.88`。

一句话:**泛域名是「要什么」,泛解析是「怎么给」。** 泛解析的匹配优先级、和精确记录怎么共存,是下一篇 [[DNS 泛解析与查询链路]] 的主题。

---

## 1.5 通配符证书(wildcard certificate)

有了泛域名和泛解析,HTTP 能通了。但要上 HTTPS,还需要证书**认可**这个泛域名。

普通证书只对**一个写死的域名**签发(`CN=oa.zhuanspirit.com`),换个子域就报证书错误。通配符证书则是给 `*.zhuanspirit.com` 签发,一张证书覆盖这一层所有子域。

它同样受 1.3 那条规则约束:`*.zhuanspirit.com` 的证书**不能**用在 `a.b.zhuanspirit.com` 上。细节(为什么只覆盖一级、多级怎么办、SAN、DNS-01 签发)见 [[通配符 HTTPS 证书]]。

## 1.6 四个词的关系速查

| 词 | 是什么 | 层面 | 例子 |
| --- | --- | --- | --- |
| 子域名 | 一个具体写死的名字 | 命名 | `oa.zhuanspirit.com` |
| 泛域名 / 通配符域名 | 带 `*` 的名字形态,匹配某一层任意前缀 | 命名 | `*.zhuanspirit.com` |
| 泛解析 | DNS 里的一条 `*` 记录,让泛域名真正能解析到 IP | DNS 解析 | `*.zhuanspirit.com A 1.2.3.4` |
| 通配符证书 | 覆盖 `*.` 一层所有子域的 HTTPS 证书 | TLS 加密 | 给 `*.zhuanspirit.com` 签的证书 |

一条完整链路串起来:**买一个域名 → 用泛域名规划命名 → 配泛解析让它能解析到机器 → 配通配符证书让它能上 HTTPS → nginx 按具体子域名转发到不同服务。** 这条链路就是本系列 2~4 篇的骨架。

---

## 1.7 为什么要用泛域名(动机)

放在最后,因为理解了上面的机制,动机就很自然:

1. **免去逐个配置**。多环境、多人、多机器场景,不用每来一个名字就手动加一条 DNS / 一张证书 / 一段 nginx。一条 `*` 全包。
2. **一套配置,任意前缀即开即用**。典型如多租户 SaaS(每个客户一个子域)、按人/按分支的测试环境(`oa-{人名}.test.xxx`)、按 PR 的预览环境。
3. **减少切换成本**。引出本系列的内部场景里,原来本地/测试环境要来回切 whistle 代理配置,泛域名让不同机器天然区分,直接用域名访问即可(代价:需要前端资源支持运行时动态定位,这正是重头那篇 [[../前端/前端运行时动态 base 完全指南]] 要解决的)。

> 权衡提醒(来自原始文档的判断):泛域名不是银弹。它省的是「逐个配置 / 来回切换」,但本地开发、后端测试环境该配的还得配。它更适合「一次构建、多处访问」的场景,而不是取代所有代理。
