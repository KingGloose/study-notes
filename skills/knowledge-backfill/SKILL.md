# Knowledge Backfill · 知识回填到学习笔记

把在**任何项目目录**里获得的有价值知识,回填到个人 LLM Wiki 学习笔记库。
你(AI)当前大概率不在笔记库目录中——本 skill 指导你跨目录、按库的约定正确写入。

## 目标库

- **本 skill 就住在目标库内部**:`<库根>/skills/knowledge-backfill/SKILL.md`。
  目标库根目录 = 本文件所在目录的上两级(`../../`)。
- **定位方式**:迁移到其他电脑后,始终以"本 skill 文件的上两级目录"为库根,
  不要依赖绝对路径。当前部署在 `/Users/zhangjiahui04/学习笔记`。
  若不确定,先确认库根下有 `AGENTS.md` + `index.md` + `wiki/` + `archive/` 再操作。
- 模式:Andrej Karpathy 的 LLM Wiki(唤醒 + 沉淀)。
- **执行前必读**:库根的 `AGENTS.md`(维护契约)和 `index.md`(现有知识点),遵循其约定。

库结构:
```
<库根>/
├── AGENTS.md   # 维护契约,先读
├── index.md    # 知识点唤醒索引
├── log.md      # 流水账
├── raw/        # 原始资料(只读留档)
├── assets/     # 新库图片
├── wiki/       # AI 沉淀的知识,按领域分子目录(前端/ai/python/...)
├── skills/     # 库自带的维护 skill(含本 skill),随库迁移
└── archive/    # 旧笔记归档,不动
```

## 核心判断:值不值得回填

一句话标准:**这个经验,半年后用户遇到类似问题时会想翻出来看吗?**

**值得(真金 —— AI 给不出的):**
- 踩坑 + 解法:花了较长时间/非显而易见才定位的问题,尤其"网上没标准答案、靠试出来"的。
- 有上下文的决策:这个项目为什么选 A 不选 B,当时的约束和权衡。
- 非文档化行为/边界条件:"这个 API 在 X 情况下静默失败""这配置只在 Y 环境生效"。
- 用户实践验证过的最佳实践(不是抄文档)。

**不值得(只进 index 唤醒,或不记):**
- 通用 API 用法、标准配置 —— AI 随时能答。
- 一次性、不会再遇到的琐碎问题。

不确定时,问用户一句"这个要记进学习笔记吗?",别自作主张。

## 回填流程

1. **确认意图**:用户同意回填后再动手。

2. **提炼**:把项目里的经验整理成结构化内容。踩坑类推荐结构:
   ```
   ## 问题现象
   ## 根因
   ## 解法
   ## 适用条件 / 边界
   ## 上下文(哪个项目、什么环境、什么版本)
   ```
   决策类:背景 / 候选方案 / 权衡 / 最终选择 / 原因。

3. **判断去处**:
   - 有个人上下文/踩坑/决策 → 写 `wiki/<领域>/<描述性文件名>.md`。
   - 纯通用知识点 → 只在 `index.md` 加一行关键词(唤醒),不写详细页。
   - 完整原始上下文(长报错日志、排查对话)若有价值 → 存 `raw/` 留档,提炼结论进 wiki。

4. **写入**:遵循库的写作约定(中文为主、`# 1.`/`## 1.1` 标题风格、代码用围栏、优先文字少截图)。
   - wiki 内部按领域分子目录,已有则归入,没有则新建(如 `wiki/前端/`、`wiki/ai/`)。
   - 标注来源上下文,让未来可追溯。

5. **更新索引**:在 `index.md` 对应领域补上新知识点关键词(带 ⭐ 标记个人实践内容)。

6. **记流水账**:在 `log.md` 追加一条,格式 `## [YYYY-MM-DD] ingest | 摘要`。

7. **可选建双链**:如果新页和已有 wiki 页相关,用 Obsidian `[[...]]` 双链关联,让知识网变活。

## 注意

- **不要动 `archive/`** 里的旧笔记内容。
- **不要把 AI 能直接答的通用知识写成详细 wiki 页** —— 那种只进 index 唤醒。
- 回填是"提炼 + 记账",用户负责判断与拍板,你负责结构化和 bookkeeping。
- 写入时用库根的绝对路径(库根 = 本 skill 文件的上两级目录),不要 hardcode 具体用户名下的路径。
