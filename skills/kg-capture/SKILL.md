# kg-capture · 跨项目知识捕获

把在**任何项目目录**里获得的有价值知识，回填到学习笔记库。

**你（AI）当前大概率不在笔记库目录里** —— 本 skill 指导你跨目录、按库的契约正确写入。

## 定位：这是「出口」的反面

| | 摄入类（kg-bilibili / kg-doc / kg-zhihu…） | **kg-capture** |
|---|---|---|
| 场景 | 在笔记库里消化外部资料 | **在别的项目里**干活时有收获 |
| 输入 | 链接、文件 | 刚踩的坑、刚做的决策、刚发现的边界 |
| 方向 | 外部资料 → 知识库 | **跨目录**把工作现场经验 → 知识库 |

## 定位库根（关键，不能出错）

- 本 skill 文件在 `<库根>/skills/kg-capture/SKILL.md`
- **库根 = 本文件所在目录的上两级**（`../../`）
- **不要 hardcode 绝对路径** —— 换电脑/换用户名仍有效
- 不确定时先确认库根下有 `AGENTS.md` + `index.md` + `wiki/` 再动手

**执行前必读库根的 `AGENTS.md`**（维护契约），遵循其全部约定。

## 核心判断：值不值得沉淀

一句话标准:**这个经验,半年后主人遇到类似问题时会想翻出来看吗?**

**值得（真金 —— AI 给不出的）:**
- **踩坑 + 解法**:花了较长时间/非显而易见才定位的,尤其"网上没标准答案、靠试出来"的
- **有上下文的决策**:这个项目为什么选 A 不选 B,当时的约束和权衡
- **非文档化行为/边界条件**:"这个 API 在 X 情况下静默失败""这配置只在 Y 环境生效"
- **主人实践验证过的最佳实践**（不是抄文档）
- **推翻了原有认知的发现**:"我以为 X,实际是 Y" —— 这类最值钱

**不值得（只进 index 唤醒,或干脆不记）:**
- 通用 API 用法、标准配置 —— AI 随时能答
- 一次性、不会再遇到的琐碎问题
- 还没验证的猜测（先验证，或明确标注"未验证"）

**不确定时问主人一句「这个要记进学习笔记吗」,别自作主张。**

## 何时主动提议（不要等主人开口）

在其他项目里出现这些信号时，**主动问一句**：

- 排查耗时明显偏长（来回试了好几轮才定位）
- 主人说出"原来是这样""难怪""坑""终于好了"这类话
- 做了有取舍的技术选型（用了 A 没用 B，且有理由）
- 发现文档没写的行为、版本特定的坑、环境相关的差异
- 主人明确表达"这个有意思""下次可能还会遇到"

提议要**具体**，不要泛泛问"要记录吗"：

> 「刚才那个 curl_cffi 的 stream 响应不支持 context manager 的坑，
> 花了两轮才定位，而且官方文档没写。要记进知识库吗？」

## 回填流程

### 第 1 步：先查重（本 skill 相比旧版的关键升级）

**别急着写新页** —— 库里可能已经记过，或有该建双链的相关页：

```bash
cd <库根>/skills/kg-ask && source ../.venv/bin/activate
python scripts/search_vault.py "<关键词>" --scope wiki
```

三种结果：
- **已有相同主题的页** → 补充进那页，不要新建重复页
- **有相关但不同主题的页** → 新建页 + **和它建双链**
- **完全没有** → 新建页

### 第 2 步：提炼成结构化内容

**踩坑类**推荐结构：
```
## 问题现象
## 排查过程（可选，但"错误的假设"往往比正确答案更有价值）
## 根因
## 解法
## 适用条件 / 边界
## 上下文（哪个项目、什么环境、什么版本）
```

**决策类**：背景 / 候选方案 / 权衡 / 最终选择 / 原因（+ 什么情况下会推翻这个选择）

**认知推翻类**：我原以为 X / 实际是 Y / 为什么会误解 / 正确的心智模型

### 第 3 步：判断去处（按 AGENTS.md）

- 有个人上下文/踩坑/决策 → 写 `wiki/<领域>/<描述性文件名>.md`
- 纯通用知识点 → 只在 `index.md` 加一行关键词（唤醒），**不写详细页**
- 完整原始上下文（长报错日志、排查对话）有价值 → 存 `raw/` 留档，提炼结论进 wiki

### 第 4 步：写入

遵循库的写作约定：中文为主、`# 1.` / `## 1.1` 标题风格、代码用围栏、优先文字少截图。

- wiki 内部按领域分子目录，已有归入、没有则新建
- **标注来源上下文**：哪个项目、什么时间、什么环境版本 —— 让未来可追溯
- **区分「实测验证的」和「AI 补充的」** —— 这是 AGENTS.md 的硬要求

### 第 5 步：更新索引与流水账

- `index.md` 对应领域补关键词（个人实践内容带 ⭐ 标记）
- `log.md` 追加一条：`## [YYYY-MM-DD] capture | 摘要`

### 第 6 步：建双链 + 体检

```bash
cd <库根>/skills/kg-lint && python scripts/lint_vault.py
```

确认新页不是孤儿页、没有死链、index 有唤醒条目。
**新页至少要有一条双链** —— 否则它是知识网的孤岛。

## 注意

- **不要动 `archive/`** 里的旧笔记内容
- **不要把 AI 能直接答的通用知识写成详细 wiki 页** —— 那种只进 index
- 回填是「提炼 + 记账」：**主人负责判断与拍板，你负责结构化和 bookkeeping**
- 敏感信息（内网地址、密钥、客户名、未公开业务细节）**不要写进库** ——
  库可能同步到 GitHub。必要时用占位符或泛化描述
- 在其他项目里操作时，**只往笔记库写，不要动那个项目的文件**（除非主人要求）

## 与其他 skill 的配合

```
其他项目里有收获
  → kg-capture 提议 → 主人同意
  → kg-ask 查重（避免重复/找双链候选）
  → 提炼 → 写 wiki + index + log
  → kg-lint 体检（确认接入知识网）
  → 以后 kg-review 会把它挑出来回顾
```
