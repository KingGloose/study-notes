# kg-review · 知识回顾

Karpathy LLM Wiki 模式的隐含前提:**知识要被反复唤醒才有价值**。
写完就存着 = 死档案。本 skill 负责挑页,**真正的回顾靠对话完成**。

## 何时用

- 「回顾一下」「随便挑几页复习」
- 「上个月记了什么」→ `--strategy recent`
- 「有哪些页我一直没再看过」→ `--status`

## 环境

无额外依赖（纯标准库）。

```bash
cd 学习笔记/skills/kg-review && source ../.venv/bin/activate
```

## 用法

```bash
python scripts/pick_review.py                        # 默认挑 3 页（stale）
python scripts/pick_review.py --count 5
python scripts/pick_review.py --strategy random      # 打破惯性
python scripts/pick_review.py --domain AI            # 限定领域
python scripts/pick_review.py --status               # 各页回顾情况总览
python scripts/pick_review.py --mark "wiki/AI/xxx.md"  # 标记已回顾
```

## 四种挑选策略

| 策略 | 挑什么 | 什么时候用 |
|------|--------|-----------|
| `stale`(默认) | 从未回顾 > 最久没回顾 | 常规回顾 |
| `recent` | 最近沉淀的 | 巩固新知识 |
| `random` | 随机 | 打破惯性，可能翻出意外的老页 |
| `orphanish` | 双链最少的 | 知识网边缘，最容易被彻底遗忘 |

## 回顾方式（本 skill 的核心，比挑页更重要）

**先回想，再看答案。** 直接把页面内容念一遍等于没回顾。

1. **只给标题和主旨**，问主人「还记得这页讲什么吗」。等他自己回想。
2. **用小节标题当考点**——脚本会列出该页的小节，可以逐个问「这节讲的是什么」。
3. **含 ⭐ 个人判断的页**（脚本会标出来）：重点问「**现在还认同当时的判断吗**」。
   知识会过时，判断会变。这是回顾比重读更有价值的地方。
4. 主人想不起来 → 再展开对应段落。**这时的记忆才是被真正唤醒的。**
5. 回顾完 `--mark <路径>` 记一笔。

## 回顾中发现问题怎么办

回顾常会暴露三类问题，按 `AGENTS.md` 处理：

- **内容过时了** → 提议更新那页，标注"原判断 vs 现在的看法"，不要直接抹掉旧判断
  （判断的演变本身是有价值的记录）。
- **当时的判断现在不认同了** → 在页里加一段说明变化和原因。
  这比删掉重写有价值——记录"我为什么改主意"。
- **这页其实没用** → 和主人确认后可以删。**沉淀过不等于永远该留着。**

## 与其他 skill 的配合

```
kg-review 挑页 → 对话回顾 → 发现过时/要补 → 摄入新资料(kg-*)补充 → 更新 wiki
                          → 发现孤立 → kg-lint 看是否该建双链
```

## 边界

- **只挑 `wiki/`**，不回顾 `raw/`（那是原始留档）和 `archive/`（旧世界封存）。
- 回顾记录存 `.review-log.json`（已 gitignore，各机器独立）。
- 不做强制排期/提醒——按 `AGENTS.md` 的「一切按需」，主人想回顾时才回顾，
  **不搞 Anki 那种打卡压力**。

## 已验证

- `stale` 策略正确把"从未回顾"的页排前（17 页均未回顾时按此排序）。
- 主旨提取准确（能从"一句话主旨"小节或首个引用段抓到）。
- 小节列表可当考点（如 AI Native 那页抓到"论证脉络/管理塌缩与三柱架构/Death of ego 是有边界的"）。
- 正确识别含个人判断的页（KimiCode 那页标出 ⭐，因为它有 §1.9 主人的对照观察）。
- `orphanish` 正确挑出链入最少的（子进程 spawn / QuillJs / Vue watch，均链入 1）。
- `--mark` 后 stale 排序正确变化（已回顾的页退出优先队列）。
