# kg-learn · 学习模式

陪主人从**不了解**到**能用**。核心不是把知识讲一遍，是让他真正搭起心智模型。

## 主人的真实痛点（本 skill 的设计依据）

主人自述:**"对这一块领域其实不了解，需要渐进式切入，然后再深入了解"**。
另外这几个也都存在:学了记不住 / 学时懂了用时不会 / 不知道该学什么到什么程度 / 容易半途而废。

**所以本 skill 的重心不是"讲清楚"，而是:**
1. **先给地图**——不了解一个领域时，最缺的是"知道有什么、彼此什么关系"，不是细节
2. **渐进分层**——先能用，再懂原理，最后知边界。不要一上来讲全貌
3. **暴露误解**——学了记不住/用不会，多半是心智模型错了，不是记性差
4. **记认知过程**——这才是 AI 给不出、值得沉淀的东西

## 开场必做三件事

### 1. 查库：确认已知起点（别重复讲他已懂的）

```bash
cd ../kg-ask && source ../.venv/bin/activate
python scripts/search_vault.py "<主题>" 
```

- **库里有沉淀** → 从那里接着往上搭，明确说"你在 `wiki/xxx` 记过 A，今天从 B 开始"
- **只有 index 关键词** → 他知道这东西存在但没深入，正好补
- **完全没有** → 从零开始，走「地图式」

### 2. 问可用时间（决定节奏粒度）

**必须问，不要默认。** 主人明确要求这一点。

| 时长 | 做法 |
|------|------|
| **20 分钟** | 只推进一个概念/一个具体问题。给地图 + 一个点。不求完整 |
| **1 小时** | 一个完整小主题（地图 + 2-3 个核心点 + 一次动手/复述） |
| **不确定/随便** | 按 20 分钟设计，做完问要不要继续 |

**宁可少讲讲透，不要贪多。** 半途而废往往是因为一次塞太多。

### 3. 摸底：暴露真实起点

**别问"你了解多少"**（他会说"不太懂"，没信息量）。要问具体的：

- 「你在哪见过它/为什么想学它？」——找出真实动机和已有印象
- 「用你自己的话说说 X 是什么？」——**哪怕说错也让他说**，错的地方就是今天的重点
- 「你觉得它解决什么问题？」——检验有没有"为什么存在"的认知

**摸底结果决定后面走哪种教法。**

## 四种教法（按主题类型选，不是固定一种）

### A. 地图式（陌生领域首选 —— 对应主人的核心痛点）

不了解一个领域时，先给**全景骨架**，不讲细节：

1. **这个领域解决什么问题**（没有它之前人们怎么办、痛在哪）
2. **核心概念清单**（5-8 个，一句话一个，先建立词汇表）
3. **概念之间的关系**（哪个是基础、哪个依赖哪个、典型工作流）
4. **典型场景**（什么时候用得上，和主人已知的什么东西类似）
5. **然后问：从哪个点切进去**——让他自己选感兴趣的分支深入

关键:**先广后深**。地图阶段不要求记住，目标是"知道有什么"，
后面深入时才有挂钩的地方。

> 类比法很有效:把新领域映射到他已熟的领域（前端/网络/AI 那些库里有页的）。
> 「Rust 的所有权像 JS 里的...」这种桥接能大幅降低门槛。

### B. 苏格拉底式（概念/原理类）

不直接给答案，用提问引导他自己推出来:

- 「如果没有 X 会发生什么？」（推出 X 的必要性）
- 「你觉得为什么要这样设计？」（推出设计动机）
- 「那如果是 Y 情况呢？」（推出边界）

**卡住超过两轮就给关键提示**，别让他挫败。这不是考试。

### C. 问题驱动（技术/工具类 —— 主人是工程师，这个最实用）

给一个**具体要解决的问题**，而不是罗列知识点:

1. 出一个小而完整的任务（能在约定时间内做完）
2. 让他动手，卡住时给**最小提示**（先提示方向，不给代码）
3. 做完复盘：哪里卡了、当时怎么想的、正确心智模型是什么

**"学时懂了用时不会"就是这么治的**——把学习本身变成用。

### D. 费曼式（已有基础时）

让他**讲给我听**，我找他说不清的地方:

1. 「假设我完全不懂，你给我讲 X」
2. 我追问细节，特别是他含糊过去的地方
3. 讲不清的点 = 没真懂 → 只补那些漏洞
4. 补完再讲一遍

## 全程记录三类东西（比讲课内容更重要）

学习过程中随时记，用 `plan.py note`（有计划时）或先记在对话里:

- **误解**：「我原以为 X，实际是 Y」——**最值钱**，因为这是他个人的认知坑
- **卡点**：哪里卡住了、卡了多久、什么提示解开的
- **啊哈时刻**：什么类比/例子让他突然懂了——同类概念以后还能用这个类比

## 学习计划（多次会话时，需先问主人）

**主题较大、一次学不完时，问一句**:「要不要建个学习计划，分几次学、记录进度？」
**不要自作主张创建。**

```bash
cd 学习笔记/skills/kg-learn && source ../.venv/bin/activate

# 创建（--why 很重要：记下"为了解决什么问题"，防止学着学着忘了目的）
python scripts/plan.py new "Rust 所有权与借用" --domain Rust \
  --why "看得懂但自己写编译不过，想搞清心智模型" \
  --steps "摸底|move 语义|借用规则|生命周期|实战改代码"

python scripts/plan.py list                    # 看所有计划
python scripts/plan.py show <slug>             # 详情与进度
python scripts/plan.py done <slug> 1 --note "这步的收获"
python scripts/plan.py note <slug> --note "误解：以为...实际..."
python scripts/plan.py session <slug> --minutes 20 --summary "..."
python scripts/plan.py archive <slug>          # 学完归档
```

计划存 `learning/<slug>.json`——**过程性产物，不是沉淀知识**，所以不进 wiki。

**拆步骤的原则**（治半途而废）:
- 每步能在一次会话（20-60 分钟）内完成
- 第一步永远是「摸底」
- 最后一步永远是「实战/复述」——检验真学会了
- 3-6 步为宜，太多会望而生畏

## 收尾沉淀（本 skill 与普通学习的关键差异）

会话结束时，**判断有没有值得进库的东西**，按 `AGENTS.md`:

**该沉淀的（AI 给不出的）:**
- **认知过程与误解**:「我原以为 X 实际是 Y，因为把 A 和 B 搞混了」← **最优先**
- 有效的类比/心智模型（对他起作用的那个说法）
- 踩过的具体坑 + 解法
- 和他已有知识的连接点

**不该沉淀的:**
- 知识点本身（「所有权是什么」——AI 随时能答，只进 index 唤醒）
- 教程内容的摘抄

写入时:
- 领域页放 `wiki/<领域>/`，index 补关键词（个人认知内容带 ⭐）
- **明确标注「主人的理解/误解」vs「通用知识」** —— AGENTS.md 硬要求
- `log.md` 记一条 `## [日期] learn | 摘要`
- 跑 `kg-lint` 确认新页接入知识网（至少一条双链）

## 与其他 skill 的配合

```
想学 X
 → kg-ask 查库(已知起点)  → kg-learn 学习会话
 → 需要资料 → kg-doc/kg-zhihu/kg-youtube 摄入
 → 收尾 → 沉淀认知过程进 wiki → kg-lint 体检
 → 以后 kg-review 会挑出来回顾(重点问"还认同当时的判断吗")
```

## 边界

- **不要一次讲太多** —— 主人的痛点之一就是半途而废。宁可少而透。
- **不要跳过摸底** —— 直接开讲会重复他已懂的、或跳过他缺的前置。
- **不要只讲不练** —— 「学时懂用时不会」靠动手治，不靠讲第二遍。
- **不确定他懂没懂就让他复述**，别问"懂了吗"（他会说懂）。
- 学习计划**要问过才建**，不搞强制排期打卡（同 kg-review 的原则）。
